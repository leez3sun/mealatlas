# 数据与营养计算方法

## 当前原型

本仓库的首批食谱是产品交互演示数据。每份营养值来自公开食物成分数据的常识级估算与原料克重加总，状态统一标记为 `estimated`，不代表实验室检测，也不能替代医生或注册营养师建议。

计算口径：

```text
每份营养 = Σ（可食部克数 × 每 100 g 营养值 ÷ 100）÷ 成品份数
```

烹调损耗、吸油率、食材品牌、可食部比例和家庭量具误差都会改变结果。水、维生素 C 等字段受烹饪方式影响尤其明显，因此界面会显示数据置信等级，不用伪精确小数。

## 生产级数据路线

- 基础食材：优先接入 [USDA FoodData Central](https://fdc.nal.usda.gov/api-guide/) Foundation / FNDDS 数据；API 需要 data.gov key。
- 包装食品：使用 [Open Food Facts API v3](https://openfoodfacts.github.io/openfoodfacts-server/api/)，并保留其众包数据质量警告与 ODbL 归属要求。
- 中国食材：计划接入有明确再利用许可、版本和可追溯条目的中国食物成分数据；在获得合规数据前不宣称“中国食物营养值已权威校准”。
- 目标参考：普通成人的均衡提示参考《中国居民膳食指南（2022）》公开建议和 WHO 健康饮食原则；个体化目标必须考虑年龄、性别、体重、活动量和健康状况。

## 减脂改良

“减脂改良”是对具体配方的显式替换，不是隐藏系数。例如：减少 10 g 烹调油、将精制主食替换为全谷物、补充瘦蛋白。每项改良都保存文字说明和营养差值，用户可恢复原配方。

## 安全边界

- 不为孕产妇、儿童、肾病、糖尿病、进食障碍或其他临床人群自动开具饮食处方。
- 过敏原过滤在生产版必须是硬约束；当前演示仅展示标签。
- 随机菜单先满足餐次和筛选条件，再以能量、蛋白质、蔬果多样性与菜系重复度评分；无法满足时应明确提示，而不是静默放宽过敏约束。
